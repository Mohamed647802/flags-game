# لعبة أعلام الدول 🏳️

لعبة أعلام دول أونلاين متعددة اللاعبين، تعمل في المتصفح بدون تثبيت.
أنشئ غرفة، شارك الكود مع أصدقائك، وتنافسوا على معرفة أعلام 195 دولة —
أو العب منفردًا، أو تحدَّ نفسك بسؤال اليوم.

- **الخادم هو المرجع الوحيد (server-authoritative):** كل الأسئلة والنقاط
  والتوقيت تُحسم على الخادم، والعميل يعرض فقط.
- **تزامن زمني بأسلوب NTP:** العميل يقيس الفرق الزمني مع الخادم
  (`public/js/timesync.js`) فيُعرض السؤال على كل الأجهزة في اللحظة نفسها.
- **بدء السؤال على مرحلتين:** `q_prepare` ثم `q_start` مع `showAt`/`endsAt`
  موحّدين، فلا يسبق أحدٌ أحدًا بسبب الشبكة.
- **عربي بالكامل** مع دعم الإجابة بالكتابة الحرة (مع تصحيح الأخطاء الإملائية
  البسيطة) أو الاختيار من متعدد.

## المميزات

- غرف أونلاين بكود من 6 أحرف (بدون أحرف ملتبسة مثل `0/O/1/I/L`) أو رابط
  مباشر `?room=CODE`.
- أوضاع لعب: عدد ثابت من الأعلام، موت مفاجئ (خطأ واحد = خروج)، وأدوار
  بالتناوب، ووضع فردي (Solo)، وسؤال اليوم (Daily).
- أنظمة نقاط: بسيط (نقطة لكل إجابة صحيحة)، وسرعة (نقاط حسب الوقت المتبقي
  وسلسلة الإجابات الصحيحة)، مع مكافأة Combo.
- فلاتر: حسب القارة، الدول العربية فقط، مستوى الصعوبة، مجموعات الدول
  المتشابهة، والأقاليم (Territories).
- تلميحات (إظهار أول حرف / حذف خيارين)، وخط حياة، وإعادة الاتصال واستئناف
  اللعب بنفس المقعد والنقاط (`resume`).
- وضع العرض `?display=1` لعرض اللعبة على شاشة كبيرة.
- لوحة صدارة وشارات (badges) في نهاية اللعبة.
- **وضع «كتابة ثم تقييم بعد الوقت»** (إعداد `answerMode: write_then_judge`،
  المضيف فقط): يكتب كل لاعب اسم الدولة (أو ما يطلبه السؤال) ويرسل إجابته؛
  لا تُصحَّح الإجابات ولا تظهر أي نتيجة أثناء الوقت. عند انتهاء المؤقت
  تُجمَع الإجابات وتُعرض على **المضيف فقط** مع الإجابة الصحيحة كمرجع
  واقتراح تلقائي (مقارنة نصية موحّدة) كتلميح — لكن قرار المضيف نهائي.
  بعد تأكيد التقييم تُمنَح النقاط وتظهر النتيجة. من لم يرسل إجابة يُحسب
  خطأ. في اللعب الفردي (Solo) يُصحَّح تلقائياً، وفي الوضع المحلي يقيّم
  صاحب الجهاز. إن غادر المضيف أثناء التقييم ينتقل الدور للمضيف الجديد،
  وإن لم يبقَ مضيف متصل يُصحَّح تلقائياً فلا تتوقف اللعبة أبداً.

## قواعد المضيف (Host)

- **المضيف هو من أنشأ الغرفة فقط** (`creatorId`/`hostId` يُحفظان مرة واحدة
  عند `create_room`) ولا يتغيران أبداً بانضمام لاعب أو خروجه أو إعادة
  اتصاله أو استئنافه.
- ينتقل المضيف **فقط** في حالتين: (أ) يضغط المضيف «جعله مضيفاً» للاعب
  معيّن (`transfer_host`)، أو (ب) يغادر المضيف صراحةً أو ينقطع اتصاله
  أكثر من 90 ثانية (نافذة الاستئناف) فينتقل لأقدم لاعب متصل.
- انقطاع مؤقت (شبكة/تبديل تبويب) لا ينقل المضيف أبداً؛ عند عودة المضيف
  خلال 90 ثانية يستعيد دوره تلقائياً.
- في لقطة الغرفة (`room_snapshot`) يحمل كل لاعب حقل `isHost`، وتظهر
  شارة «المضيف» بجانب منشئ الغرفة دائماً، وزر النقل يظهر للمضيف فقط.
- 195 دولة + ~30 إقليمًا، مع عواصم وحقائق وصعوبة لكل دولة.

## التشغيل السريع

المتطلبات: Node.js ‏20+.

```bash
npm install   # يشغّل postinstall وينسخ ملفات SVG للأعلام إلى public/flags/
npm start     # يشغّل الخادم على http://localhost:3000
```

افتح `http://localhost:3000` في المتصفح.

| أمر | الوصف |
| --- | --- |
| `npm start` | تشغيل الخادم |
| `npm run dev` | تشغيل مع إعادة التحميل عند التعديل |
| `npm test` | تشغيل كل الاختبارات (`node --test test/`) |
| `npm run validate-data` | التحقق من بيانات الدول والأعلام |
| `npm run smoke` | اختبار دخان شامل (End-to-End) ضد خادم حقيقي |

## كيف تلعب أونلاين

1. افتح الموقع واضغط **إنشاء غرفة**، واختر الإعدادات (عدد الأعلام، الوضع،
   نظام النقاط، مدة السؤال، نوع الإجابة).
2. شارك الكود (6 أحرف) أو الرابط `https://your-domain/?room=CODE`
   مع اللاعبين.
3. يدخل اللاعبون بالكود أو الرابط، ويضغط المضيف **ابدأ**.
4. يظهر كل سؤال على كل الأجهزة في نفس اللحظة (`showAt`)، وتُغلق الإجابة
   عند `endsAt`.
5. في نهاية اللعبة تظهر الترتيب النهائي والشارات.

### وضع العرض

أضف `?display=1` للرابط لعرض شاشة كبيرة (مناسبة للصف أو التجمعات):
يظهر العلم والسؤال والترتيب بدون أزرار إجابة.

### اللعب الفردي وسؤال اليوم

- **فردي (Solo):** العب وحدك ضد المؤقّت، ونتيجتك تُحفظ محليًا.
- **سؤال اليوم (Daily):** سؤال واحد كل يوم، نفس السؤال لكل اللاعبين
  حول العالم (البذرة مشتقة من التاريخ عبر `GET /api/daily`).

## النشر

### Render (موصى به — الأسهل)

المستودع يحتوي `render.yaml` جاهزًا:

1. ادفع الكود إلى GitHub.
2. في Render اختر **New → Blueprint** واختر المستودع.
3. سيُنشئ الخدمة تلقائيًا (`npm ci` ثم `npm start`) مع فحص الصحة
   على `/healthz`.

### Railway

1. أنشئ مشروعًا جديدًا من المستودع.
2. اضبط متغير البيئة `PORT` (يضبطه Railway تلقائيًا عادة).
3. أمر البدء: `npm start`.

### Fly.io

```bash
fly launch --no-deploy
fly deploy
```

(تأكد من أن `fly.toml` يوجّه فحص الصحة إلى `/healthz` ويفتح المنفذ 3000.)

### VPS مع Caddy

```caddy
flags.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

Caddy يتعامل مع WebSocket تلقائيًا. شغّل الخادم كخدمة systemd:

```ini
[Unit]
Description=Flags game
After=network.target

[Service]
WorkingDirectory=/opt/flags-game
ExecStart=/usr/bin/node server/index.js
Environment=PORT=3000 NODE_ENV=production
Restart=always
User=flags

[Install]
WantedBy=multi-user.target
```

### VPS مع Nginx

```nginx
server {
    listen 443 ssl;
    server_name flags.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # الألعاب قد تبقى مفتوحة طويلًا؛ لا تقطع الاتصال مبكرًا

        proxy_send_timeout 3600;
    }
}
```

### تدفق اللعبة

1. العميل يرسل `hello` ويستقبل `welcome` مع `playerId` و`secret`
   (يُستخدمان لاستئناف الجلسة بعد انقطاع الاتصال).
2. `create_room` / `join_room` → يبث الخادم `room_snapshot` لكل اللاعبين.
3. المضيف يرسل `start` → يبدأ العد التنازلي.
4. لكل سؤال: `q_prepare` (استعد) ثم `q_start` مع `showAt` و`endsAt`
   موحّدين؛ العميل يرسل `ready` بعد التجهيز، و`answer` قبل انتهاء الوقت.
5. الخادم يرسل `answer_ack` و`player_answered`، ثم `q_reveal` بالإجابة
   الصحيحة والنقاط، وأخيرًا `game_end` بالترتيب والشارات.
6. أي رسالة غير صالحة يرد عليها الخادم بـ `error {code, message}` دون
   قطع الاتصال.

### بروتوكول WebSocket

- الاتصال: `ws://host/ws` — رسائل JSON فيها حقل `t` (النوع)، ورسائل
  الخادم تتضمن `seq` متسلسلًا.
- من العميل: `hello`، `ping {c}`، `create_room {name, settings}`،
  `join_room {code, name}`، `resume {playerId, secret, code}`، `ready`،
  `answer {choiceIndex|text, questionId}`، `start`، `leave`،
  `react {emoji}`.
- من الخادم: `welcome`، `pong {c, s}`، `room_snapshot`، `q_prepare`،
  `q_start {showAt, endsAt}`، `answer_ack`، `player_answered`،
  `q_reveal`، `game_end`، `error {code, message}`.

### مزامنة الوقت

العميل في `public/js/timesync.js` يرسل عدة عينات `ping`، ويحسب الفرق
الزمني `offset` من العينة ذات أقل زمن ذهاب وعودة (RTT) عبر الدالة
النقية `computeOffset(samples)`. بذلك يعرض كل اللاعبين السؤال في نفس
اللحظة رغم اختلاف ساعات أجهزتهم.

## إضافة دولة جديدة

1. أضف مدخلًا في `shared/countries.js`:
   ```js
   { code: 'xx', ar: '...', en: '...', aliasesAr: [], aliasesEn: [],
     continent: 'africa', capitalAr: '...', capitalEn: '...',
     difficulty: 2, isArab: false }
   ```
   - `code`: رمز ISO من حرفين (صغير).
   - `continent`: واحدة من `africa` | `asia` | `europe` | `north-america` |
     `south-america` | `oceania`.
   - `difficulty`: ‏1 (سهل) / 2 (متوسط) / 3 (صعب).
   - `similarGroup` (اختياري): اسم مجموعة تشابه (مثل `guinea` أو `congo`)؛
     يجب أن تشاركها دولتان على الأقل.
   - `capitalAmbiguous` (اختياري): `true` إذا كانت العاصمة محل خلاف.
2. تأكد من وجود ملف العلم `public/flags/xx.svg` (يُنسخ من حزمة
   `flag-icons` عند `npm install`؛ إن لم يكن موجودًا أضفه يدويًا).
3. شغّل `npm run validate-data` — يتحقق من كل الشروط (195 دولة،
   عدم تكرار الأكواد والأسماء، وجود الأعلام، كفاية كل فلتر).

## إضافة نوع سؤال جديد

1. في `shared/engine.js`: أضف فرعًا في `makeQuestion(code, settings, rng)`
   يبني السؤال الجديد (مثال: «ما عاصمة هذه الدولة؟» أو «إلى أي قارة
   تنتمي؟»)، واحرص أن يبقى شكل السؤال متسقًا: خيارات فريدة تتضمن الإجابة.
2. في `shared/engine.js`: حدّث `checkAnswer(question, payload)` لقبول
   صيغة الإجابة الجديدة.
3. في العميل (`public/js/`): أضف عرضًا للسؤال الجديد (العلم أو النص
   أو الخيارات) حسب `question.type`.
4. أضف اختبارات في `test/engine.test.mjs` تغطي النوع الجديد، ثم شغّل
   `npm test`.

## الافتراضات والقرارات

- **الخادم مرجع وحيد:** لا يثق الخادم بأي نقاط أو توقيت يرسله العميل؛
  كل شيء يُحسب على الخادم.
- **رموز الغرف** من 6 أحرف بدون `0/O/1/I/L` لتجنب الالتباس عند الإملاء
  صوتيًا.
- **أول إجابة صحيحة** في الوضع البسيط تحسم الجولة (نقطة واحدة لكل جولة).
- **الإجابة الخاطئة بالاختيار** تقفل اللاعب لبقية الجولة؛ وبالكتابة
  يُقفل بعد 3 محاولات خاطئة.
- **الموت المفاجئ:** خطأ واحد يُخرج اللاعب من اللعبة.
- **وضع الأدوار:** يجيب لاعب واحد فقط في كل جولة (حسب `turnPlayerId`).
- **الإيقاف المؤقت** يجمّد المؤقت: عند الاستئناف يُزاح `endsAt` بمقدار
  مدة الإيقاف.
- **التعادل** في نهاية الأعلام يُحسم بأعلام إضافية (tie-break) إن دعم
  المحرك ذلك، وإلا تنتهي اللعبة بالترتيب الحالي.
- **تطبيع الإجابات العربية:** إزالة التشكيل والتطويل، توحيد الألفات،
  `ى→ي`، `ة→ه`، `ؤ→و`، `ئ→ي`، وحذف `ال` التعريف؛ وخطأ إملائي واحد
  مقبول في الأسماء الطويلة — لكن «النيجر» لا تُقبل لـ «نيجيريا» والعكس.
- **الأعلام SVG** تُنسخ من حزمة `flag-icons` عند التثبيت، لذلك هي
  مستثناة من Git (`.gitignore`) وتُعاد توليدها في كل نشر.

## التوسع (Scaling)

الخادم الحالي **نسخة واحدة (single-instance)** والغرف محفوظة في الذاكرة
(in-memory). هذا يكفي لمئات الغرف المتزامنة، لكنه يعني أن:

- إعادة تشغيل الخادم تُنهي الغرف النشطة.
- لا يمكن توزيع الحمل على أكثر من نسخة.

للتوسع إلى نسخ متعددة: انقل حالة الغرف إلى **Redis** (مع Pub/Sub لبث
الأحداث بين النسخ) أو إلى **Cloudflare Durable Objects** (كائن واحد لكل
غرفة). منطق اللعبة في `shared/engine.js` خالص (pure) ولا يعتمد على
التخزين، فيسهل نقله كما هو.

## ملاحظات أمنية

- لا تُرسل أسرار أو مفاتيح في متغيرات بيئة تُبنى داخل الصورة (Docker)؛
  مرّرها وقت التشغيل فقط.
- `secret` اللاعب يُستخدم لاستئناف الجلسة؛ عامِله ككلمة مرور ولا
  تعرضه في السجلات أو الواجهة.
- حدّ المعدل (`server/ratelimit.js`) يقيّد الرسائل المتكررة من نفس
  الاتصال؛ والرسائل غير الصالحة تُرفض بـ `error` دون قطع الاتصال.
- اضبط `ALLOWED_ORIGINS` على نطاقك في الإنتاج بدل `*`، وفعّل
  `TRUST_PROXY=true` فقط خلف Proxy موثوق.
- الخادم لا يخزّن أي بيانات شخصية؛ الأسماء داخل الغرف مؤقتة وتُمسح
  بانتهاء الغرفة.
